# Optional desktop media helpers

Media tools are opt-in (`MediaEnabled=false` by default). Settings accepts explicit absolute yt-dlp and optional FFmpeg executable paths, plus an optional yt-dlp distribution license file. No tool is downloaded or installed. Normal direct media downloads still use the ordinary resolver/aria2 path without either tool.

The inspector checks the configured yt-dlp version and required safe configuration switches with bounded output/time limits. An explicit or adjacent LICENSE/COPYING file must contain a recognized distribution license. FFmpeg reports its version and `-L` license text. These checks identify the supplied tool/distribution information; they do not authenticate an arbitrary executable or prove that a supplied license file belongs to that binary. Official yt-dlp distributions have different licenses depending on bundled dependencies; see the [upstream licensing notes](https://github.com/yt-dlp/yt-dlp#licensing). FFmpeg licensing is determined by its build; see [FFmpeg legal information](https://ffmpeg.org/legal.html).

The Media window inspects one public HTTP(S) source, displays bounded filename/format/audio/video/height metadata, lets the user select exact format IDs and an optional separate audio track, previews the output filename and destination queue, and adds a persistent native media-engine download. Separate tracks are muxed into MKV using the configured FFmpeg. Audio-only and combined direct formats preserve their advertised container. The optional engine supports queue admission, stop, retry, progress, and cancellation. Pause waits for owned operations/processes to terminate and retains only its own temporary files; a retry re-inspects the source and restarts its owned byte snapshot rather than inventing a new expired request. It does not offer range-resume of partially fetched media snapshots.

## Transfer and encryption boundary

Yt-dlp only inspects metadata. Sources and permitted request context enter its configuration through stdin, with token quoting, never shell command strings or credential argv. Default configs, plugins and remote components are disabled. Metadata stdout is bounded; stderr is drained without logging or exposing signed URLs. Extracted URLs remain transient and are never added to media selections or diagnostics. Persisted selections contain only format IDs and output extension; existing download storage protects request headers through its credential mechanism.

The native engine downloads immutable snapshots of selected HTTP(S) URLs itself. Supported segmented sources are finite unencrypted HLS media playlists with ENDLIST and explicit finite DASH fragment lists reported by the inspector. HLS keys/session keys, live/partial streams, byte ranges, discontinuities, unsupported initialization changes and excessive nesting/counts are refused. DASH manifests are bounded, DTD/entity processing is disabled, and ContentProtection/DRM metadata is refused; implicit SegmentTemplate plans without an explicit finite fragment snapshot are unsupported.

Segments are copied into generated files under the download's owned workspace. FFmpeg receives only those local files with `-protocol_whitelist file`, and no decryption keys or remote manifests. A remote manifest changing after inspection cannot introduce a newly fetched key/playlist into the byte snapshot: the downloader uses the checked URL list and never decrypts segments. Completion requires successful local mux/transfer exit, a nonempty expected output, and moving that output to the reserved filename. Source format disappearance, mux failure or unsupported plans produce an error requiring inspection/retry. Cancellation terminates only owned helper process trees and closes owned HTTP operations; user browser/app/engine processes are untouched.

## Explicit limitations

Adapter restrictions and all proxy policies are rejected before helper probing, manifest requests or transfers because enforcement for these optional helpers has not been proved. Each accepted download retains its explicit network-policy snapshot; changing a default does not rewrite existing download policies. Authentication cookies, Authorization and custom headers are also refused: yt-dlp extractor headers cannot be safely scoped across arbitrary format hosts. Public Accept/Accept-Language, bounded user agent, and origin-only referrer may be supplied. Authenticated direct files remain supported through the normal direct-download path.

Media supports one connection per transfer. A per-download rate limit and the media engine's assigned share of the global rate limit are paced dynamically; unsupported segmented-connection options are refused. Engine concurrency is additionally reduced when a small nonzero byte cap cannot allocate at least one byte/second per transfer. Network/process behavior on other operating systems is not established by a build alone.

## Validation

Pure regressions cover metadata/DRM/playlist limits, format/path injection, unsupported network/auth context, HLS key/live/scheme rejection, finite DASH snapshots, and stdin quoting/referrer-query removal. The coordinator owns serialized .NET test/build execution and any real helper/browser/network fixture runs. This document describes implemented boundaries without claiming runtime verification of an installed yt-dlp/FFmpeg distribution, every media site, or cross-platform adapter enforcement.
