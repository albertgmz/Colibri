# Capture policy ownership

`capture-policy.json` is the app-owned category catalog and decision-reason vocabulary. Stable lowercase category IDs map to the existing Core category enum and folder preferences. APK belongs to Programs. Core capture delegates classification to `CategoryMapper` after stripping path components; generated browser helpers use the same basename and last-extension rules. A known last extension takes precedence over an unknown tar suffix; otherwise the category is Other. Browser-supplied filenames take precedence over URL filenames; MIME alone does not change category.

`node scripts/generate-capture-policy.mjs` emits the Core catalog/reason constants, `docs/capture-catalog.ts`, and sibling browser catalog/rules copies. `--check` rejects drift without writing. App CI uses `--check --app-only` for its single-repository checkout; the default local check still requires matching sibling copies. `docs/capture-rules.ts` owns the browser policy evaluator and scoped exclusion representation. The sibling `node scripts/sync-contract.mjs` copies canonical artifacts and its drift test compares them with the app checkout. Cross-repository CI requires the configured read token; local sibling checks run without it. Extension identities and the native host boundary are unchanged.

## Implemented capture preferences

Settings provides Capture / Ask / Keep in browser per category, validated extension overrides, the existing minimum-size preference, enabled/private controls, and scoped exclusions. Migration is additive: legacy allowlisted extensions Ask; known extensions outside the saved list Keep; completely unlisted extensions Ask through Other. Category changes clear known extension overrides in that category. Explicit extension overrides otherwise take precedence. Old clients receive a compatible allowlist/minimum representation.

GET/private restrictions and all matching exclusions always take precedence, including manual and bulk offers. `host:` matches an exact host, `domain:` includes subdomains, `path:` matches an exact host and path subtree, and `type:` matches a filename extension on any host. Rules reject queries, credentials, wildcards and controls. Original/final/redirect/referrer URLs are evaluated without retaining them in decision history. The settings page shows only a bounded in-memory reason from the most recent desktop decision.

Genuine browser downloads enter evaluation; observed arbitrary HTTP responses never independently create offers. Unknown size does not prove a download is below the minimum. `capture-policy-v1` carries optional action maps/exclusions; `automatic-capture-v1` permits automatic acquisition only after negotiation. Ask uses the existing confirmation window. Capture reuses that window's acquisition command, duplicate handling and cancellation rollback. Pending is never ownership acceptance, and browser cancellation still requires explicit authoritative acceptance after acquisition. Lost-response and process-loss limitations remain documented in `protocol.md`; this is not exactly-once delivery.

Bulk, queue, network, torrent and optional media boundaries are described in [features](FEATURES.md).
